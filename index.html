Learning journey

Roughly the order I picked things up — and the order I'd recommend to anyone starting out.

  1. Linux

    Comfortable

    Shell fundamentals, file permissions, process management, systemd services, and enough sed/awk to be dangerous.

    Field note — daily driver is Ubuntu Server on a home-lab Raspberry Pi cluster.

  2. Git

    Comfortable

    Branching strategies, interactive rebase, resolving merge conflicts without panicking, and writing commit messages I'd actually want to read later.

    Field note — rebuilt a tangled feature branch history using interactive rebase instead of nuking it.

  3. GitHub

    Comfortable

    Pull request workflows, code review etiquette, issue triage, branch protection rules, and the basics of GitHub Actions.

    Field note — set up branch protection and required reviews on a small team project.

  4. Docker

    Practicing

    Writing multi-stage Dockerfiles, keeping images small, and wiring up local dev stacks with Docker Compose.

    Field note — cut an image from 900MB to 140MB with a multi-stage build.

  5. CI/CD pipelines

    Learning

    Building GitHub Actions workflows for lint, test, and build; reading up on Jenkins before writing my first pipeline there.

    Field note — first workflow that lints, tests, and pushes an image on every merge to main.

  6. AWS

    Learning

    EC2, S3, and IAM fundamentals — working through hands-on labs toward the Cloud Practitioner certification.

    Field note — deployed a static site to S3 with a locked-down IAM policy.
